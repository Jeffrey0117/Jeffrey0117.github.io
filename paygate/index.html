它幫產品做掉的事

這些原本每個產品都要自己寫一遍，而且最容易出錯的就是這幾塊。

開結帳頁

產品後端打一個 API，拿到藍新或 PAYUNi 的刷卡網址，把使用者導過去就好。

認得是誰的錢

訂單編號開頭（KB、LS、PD…）對應到產品。兩個產品剛好同價時，也不會把錢記錯人。

前綴配對

一筆錢怎麼走

以每月訂閱為例，使用者按下「訂閱」到產品開通，中間發生的事。

  1. 產品要一張結帳單產品後端帶著使用者 email 和方案，向 PayGate 要結帳網址。
  2. 使用者在藍新刷卡卡號只經過藍新，PayGate 和產品都碰不到。
  3. 藍新回報結果PayGate 收到加密的通知，先驗章、再解密，金鑰不對的一律拒收。
  4. 入帳並展延訂閱同一筆交易就算藍新重送也只記一次，訂閱到期日照藍新的下次扣款日往後延。
  5. 通知產品與老闆打 webhook 給產品開通功能，同時推播到 Telegram。
  6. 之後每個月自動重來藍新每期扣款都會再走一次第 3 到 5 步，沒扣到就不延期，到期自然降級。

產品端只要寫這幾行

不用碰金流金鑰、不用寫解密、不用管續訂。

// 使用者每次進付費功能前問一次
const res = await fetch(
  `${PAYGATE}/api/subscription/check` +
  `?email=${email}&product=pokkit`
)
const sub = await res.json()

// { active: true, tier: "pro",
//   end_date: "2026-12-09T…", quotas: {…} }
if (!sub.active) return showUpgrade()

回傳的 active 已經把「過期」和「退費處理中」都算進去，產品不用自己判斷日期。

quotas 是方案裡定義好的額度，例如容量上限，所以改方案只要改 PayGate 一個地方。
