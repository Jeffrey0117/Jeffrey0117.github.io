自架主機的資料庫管家

資料庫備份，
交給一個 API。

自己架 PostgreSQL，最常出事的不是資料庫本身，是「上次備份是什麼時候？」。SelfBase 把備份、清舊檔、還原和健康檢查收成一個小服務：排程器每天戳它一下，它把每個資料庫都 dump 下來、記好帳，舊的照規則清掉。

它幫你顧的事

都是「平常沒人想做、出事才後悔沒做」的那幾件。

一次備份全部

一個請求把所有登記的資料庫同時 dump 下來。其中一個失敗，其他照樣完成，結果逐筆回報。

POST /api/backup/all

舊備份自己清

每個資料庫只留最近 10 份、30 天內的備份，失敗紀錄超過 7 天也一併清掉。數字都能改。

retention

一鍵還原

指定一份完成的備份就能還原，也可以還原到另一個資料庫，先在副本上確認再動正式的。

pg_restore --clean

每份備份都有帳

檔名、大小、花了幾毫秒、成功或失敗的錯誤訊息，全記在本機 SQLite，隨時查得到。

running → completed

看一眼資料庫

資料庫多大、現在幾條連線、最大的 20 張表各佔多少空間和幾筆資料，加上最後一次成功備份。

GET /api/pg/stats

Redis 還活著嗎

PING 之後讀 INFO：版本、記憶體用量與高峰、連線數、命中與未命中次數。

GET /api/redis/health

一次夜間備份怎麼跑

SelfBase 本身不帶計時器，由你現有的排程器（cron、工作排程器、PM2 之類）定時呼叫。

  1. 排程器戳一下帶著 Bearer token 呼叫 POST /api/backup/all。沒設 token 的服務一律拒絕，不會變成誰都能打。
  2. 逐庫跑 pg_dump找出所有啟用中的資料庫，同時各跑一次 pg_dump。密碼從環境變數讀，不存進資料庫。
  3. 寫檔並記帳存成「資料庫名_日期_時間.dump」，紀錄從 running 改成 completed，填上大小和耗時。單次最長等 5 分鐘。
  4. 失敗也留下證據dump 失敗就把 pg_dump 的錯誤訊息寫進紀錄、標成 failed，不影響其他資料庫。
  5. 清掉過期的備份再呼叫 POST /api/cleanup，照保留份數和天數刪檔，回報刪了幾份。
  6. 隔天早上看一眼GET /api/health 不用登入，直接告訴你各資料庫連得上沒、Redis 狀態、最後一次備份的時間和結果。

裝起來只要這幾步

Node.js 加上主機上已經有的 PostgreSQL 命令列工具就夠了。

# 1. 安裝並啟動（預設 port 4023）
npm install
npm start

# 2. .env 需要的變數（值自己填）
#   SELFBASE_TOKEN   API 的 Bearer token
#   PG_BIN_PATH      pg_dump / psql 所在資料夾
#   PG_PASSWORD      或 PG_PASSWORD_<ID> 分庫設定

# 3. 登記要備份的資料庫
curl -X POST $SELFBASE/api/databases \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"id":"shop","db_name":"shop"}'

# 4. 交給排程器，例如每天 03:00
0 3 * * * curl -X POST $SELFBASE/api/backup/all \
  -H "Authorization: Bearer $TOKEN"

登記時沒填的欄位用預設值：主機 localhost、port 5432、使用者 postgres。刪除是停用，不會刪掉已有的備份紀錄，同一個 id 再登記一次就恢復。

每個資料庫可以有自己的密碼：id 是 shop 就讀 PG_PASSWORD_SHOP，沒有才用共用的 PG_PASSWORD。

第 4 步的 cron 只是例子，任何能定時發 HTTP 請求的工具都行。

呼叫的工具與服務

pg_dump備份 pg_restore還原 .dump psql還原 .sql · 查統計 Redis本機 6379 MemuraiWindows 服務 SQLite備份帳本

目前寫給 Windows 主機：預設的 PostgreSQL 路徑是 Windows 版 16，Redis 啟動用 Windows 服務。換到 Linux 要改 PG_BIN_PATH。
