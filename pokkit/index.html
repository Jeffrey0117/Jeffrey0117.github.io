一支大影片怎麼傳上去

以一支幾百 MB 的手機影片為例，從選檔到拿到連結，中間發生的事。

  1. 選檔、選期限要不要密碼、多久過期，上傳前先選好。密碼只跟著最後一個請求送出，不會存在上傳紀錄裡。
  2. 先問容量夠不夠檔案還沒開始傳，伺服器就先比對你的方案剩多少空間。不夠就直接告訴你，不讓你白傳幾百 MB。
  3. 切成 16 MB 一塊超過 64 MB 的檔案走分塊上傳，同時送 3 塊。每個請求都很小，過得了代理伺服器 100 MB 的單次上限。
  4. 斷了就接著傳某一塊失敗會自動重試 3 次；整個斷線的話，未完成的上傳保留 24 小時，回來可以續傳。
  5. 重組、入庫所有塊到齊後在伺服器上組回原檔。照片和影片在背景產縮圖、轉檔，你不用等。
  6. 拿到連結回傳 /f/ 開頭的分享網址，網頁版會自動複製到剪貼簿。

給開發者：每個專案一把金鑰

自己的其他專案要存圖片、影片，就開一個專案帳號，拿一把 pk_ 開頭的金鑰。各專案只看得到自己的檔案。

import { createPokkit } from './pokkit-client.mjs'

const pokkit = createPokkit({
  baseUrl: 'https://your-pokkit.example',
  key: process.env.POKKIT_KEY, // pk_…
})

// 路徑、Buffer、Blob 都可以
const { id } = await pokkit.upload('./photo.jpg')
pokkit.url(id)   // → …/f/{id} 分享網址

const files = await pokkit.list({ limit: 50 })
await pokkit.remove(id)

sdk/pokkit-client.mjs 是一個單檔，Node 18 以上直接用，金鑰放在 X-Pokkit-Key 標頭。

檔案超過 64 MB 時，upload() 會自動改走 /api/upload/chunked 分塊上傳（需要另外裝 chunked-upload-kit）。失敗時錯誤會帶 uploadId，丟回去就能續傳。

金鑰在伺服器上只存雜湊值，後台可以隨時換一把新的，舊的立刻失效。
